# Roadmap

Every release advances executable vertical slices. A feature's presence in this roadmap is not implementation evidence. Machine-readable status is in implementation-status.json.

1. **Current:0.2.0-dev — inspectable rollback workflow.** Management API/CLI, PostgreSQL workflow/audit, strict policies, actual Kubernetes CRD/controller, read-only console, tests, local deployment configuration. Live pod recovery and container startup still need a developer Docker/Kind machine.
2. **Next: verified one-cluster local release.** Run fresh Docker builds and image scans, actual failed image rollout recovery in Kind, negative authorization with unchanged resource, console showing its persisted timeline. Add a reproducible all-in-one lab launcher and authenticated in-cluster installation. Record real pod/log/request evidence and RTO. Fix observed failures before advancing.
3. **Outbound connectivity and two-cluster lab.** Agent enrollment/mTLS, versioned command protocol, bounded buffer/reconnection, cluster identities/revocation, inventory plus metrics-server integration, isolated test namespaces, durable command leases and independent timeout sweeper. No cluster-admin distribution.
4. **Durable events and delivery.** Normalize state tables and migrations; transactional outbox; NATS durable consumers, version/ordering/deduplication/dead-letter tests; Jenkins execution; signed image digests; reviewed GitOps updates; Argo CD ownership and rollout health. Demonstrate GitHub-to-cluster pipeline with actual evidence.
5. **Reliability and observation.** Reference multi-service application with real request metrics/logs/traces, Prometheus SLI/SLO/burn calculations; OTel trace propagation; ELK ingestion/search/retention; topology/deployment registry, progressive delivery verification and all management pages.
6. **Security and controlled resilience.** OIDC tenant isolation, policy schema evolution, individual approvals, expiry, signature verification, supply-chain scanning, chaos experiments with target/hypothesis/abort/duration, test-only route failover with fencing, measured outage/recovery results, backups/restores and database integrity checks.
7. **Infrastructure and scale.** Ansible lab/Jenkins host preparation; complete validated AWS Terraform EKS/network/IAM/storage/registry path before Azure/GCP. Billable apply only with explicit approval. Per-target transactional admission, controller partitions, retention, fair quotas, real PG/cluster load tests and measured limits. Enterprise and multi-region claims require separate evidence.

Contribution entry points: service invariant/property tests; strict OpenAPI schemas; CRD status conditions and envtest manager tests; local-lab diagnostics; accessible console interactions; documentation validated on WSL2/macOS/Linux. Discuss changes to execution trust boundaries before implementation.
